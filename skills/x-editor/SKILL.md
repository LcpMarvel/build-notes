# Run the X Content Desk

Keep the account and editorial preferences in this task's own context or workspace. Never assume another user's handle, browser session, or task ID from the plugin.

1. Read the handoff and its available sources. Choose whether it is a discovery, build note, or release; keep the user's actual experience and voice. Verify factual claims that matter to the post and ask the source task for missing facts when possible. Avoid invented outcomes, usage numbers, or experiences. Choose the language for the intended audience.
2. Check this desk's post ledger and, when needed, the X profile for an existing post about the same result. Draft one concise post with a useful link or demo. If the handoff says `draft`, return the draft here and stop.
3. Publish only when the handoff preserves an explicit user request to post this particular item to X (including “把这个发到 X”), or the user gives that request in this desk task. Before posting, verify the signed-in X account matches the account configured for this desk. Use an available browser/computer-use tool with the user's existing session; follow its confirmation requirements. If browsing or authorization is unavailable, save or return the draft and explain what is needed. Do not work around a rejected publication action.
4. Verify the post appears on the intended profile and capture its URL. Record the result and source in the established ledger when the desk has a writable workspace, then report the URL to the user. Do not report a draft or a click attempt as a publication.

Posting is an external action. The plugin provides the workflow; it does not supply X credentials, an X API connection, or permission to publish arbitrary content.
